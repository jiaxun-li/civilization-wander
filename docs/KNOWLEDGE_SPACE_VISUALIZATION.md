# V6 知识空间可视化设计

## 1. 状态与目标

本文是 V6 知识空间可视化的权威设计契约。第一轮终点是在电脑上通过专用
本地命令打开一个独立预览，读取完整、已通过门禁的 V6 knowledge core，展示
Region×时间切片。预览用于验证空间模型和视觉语法，不替换 Civilization
Wander 的 Card-first 正式网站。

当前正式 V5 入口、聚合器、常规 Vite build 和 GitHub Pages workflow 不得
导入预览或 `v6/`。预览必须拥有独立 HTML／TypeScript 入口和构建边界；在
实现完成前，文档不把任何拟定命令描述为已经可用。

第一轮明确不包含：

- 关系线和 TemporalRelation 可视化；
- 跨概念层投影；
- Card／Scene 正文、图片、媒体或导航；
- 搜索和筛选；
- 可旋转的 3D 总览或“返回 3D”按钮；
- GitHub Pages 发布或正式 V5 运行时切换。

后续用户已批准选中详情补充简介、参与者、地域角色和可展开来源。Entity 简介
使用其 `canonicalSummary`；Event 简介复用经审核的 V5 公共事实段落，冻结在
预览专用的 `adapters/event-descriptions.ts`，保留原 claim ID 与 claim 级来源。
不运行时导入 V5，不展示内部 EditorialReview，也不扩展为完整 Card／Scene。
政权背景、关系线、重叠选择改造、节点点击尺寸及裁切提示目前仍暂缓；本轮
不按时空重叠自动分配文明归属，不用未经核实的旗帜替代政权名称。

政权与文明色块现采用按 Entity 身份维护的固定编辑配色。同一对象的各 Phase、
Region 放置、折叠缩略图与详情色标保持同色；不同对象分别配色并保留短名称。
颜色登记位于预览呈现层，不写入历史核心，不将文化作品或事件自动染成某个
政权的颜色。这些颜色用于识别，不声称来自古代旗帜。

## 2. 三维知识空间

知识空间固定使用三个语义维度：

- 时间：连续历史时间；
- Region：有层级、有人工作者顺序的文化—地理区域轴；
- 概念层：从物质对象到抽象思想的受控概念轴。

这三个维度组成 renderer-neutral 的空间模型，不等于某个 SVG 坐标系或
Three.js scene。所有渲染器都必须消费同一批语义 mark 和 slice selection。

规划中的三种切片是：

1. Region×时间，固定一个概念层；
2. 概念层×时间，固定一个 Region；
3. Region×概念层，固定一个时间点或时间窗口。

第一轮只实现第 1 种。概念层按钮必须单选，默认显示“政权、制度与社会”，
且不提供“全部”；“全部”会构成尚未批准的跨层投影。第 2、3 种可以先建立
类型和纯函数契约，但不得作为未完成标签或无效控件出现在预览中。

未来 3D 总览是观察三维空间和选择切面的入口，不是密集阅读界面。进入一个
切片后只显示“返回 3D 视图”，不并列显示三个兄弟切片标签。3D 尚未实现时，
第一轮预览直接进入 Region×时间，也不显示无效的返回按钮。

## 3. 五种语义标记

知识空间只使用五种基础标记。名称描述语义，不描述具体 SVG path：

| 标记 | 中文语义 | 典型对象 | 第一轮视觉 |
|---|---|---|---|
| `block` | 实体块／面 | 稳定的政权、制度、社会或共同体 | 不透明实心长矩形 |
| `node` | 节点／点 | 单次历史事件、具体文学作品 | 小菱形，未来可替换为图标 |
| `trace` | 实体轨迹／迹 | 人物、城市、建筑、遗址、历史过程 | 有少量宽度、两端收尖的实体线，视觉上是拉长的菱形 |
| `crayonStrip` | 蜡笔细条 | 文学传统、技术、生产、贸易、艺术等持续存在或传播 | 窄而连续、边缘有材料感的蜡笔条 |
| `crayonField` | 蜡笔场 | 广泛覆盖当地社会生活的语言、文字或宗教环境 | 可跨 Region 的疏松蜡笔区域 |

标记种类由历史对象的存在方式决定，而不是由“真实／抽象”印象、时间精度、
Region 精度或对象 ID 决定。renderer 不得为个别 ID 编写视觉特判。

### 3.1 神话与史诗采用简洁的作品节点

按本轮用户决定，神话故事与史诗优先保留一个 `literaryWork` 作品节点，
使用来源支持的代表性成文年代和一个有依据的关联地域。删除重复的口头形成、
传抄和传播传统对象及其阶段，不增加展开层级。宗教本体不等于某一篇神话作品。

代表成文年代使用 `approximate: true`；世纪级年代可用该世纪的代表坐标，
公开标签仍显示“约某世纪”，不能称为已知的精确撰写年。如果无法支持较窄的
成文年代，保留不确定区间并绘制单个作品节点，不恢复传播长条。版本选择与
删减理由保留在 V6 迁移审计；不把神话情节转为历史事件。

## 4. 蜡笔细条与蜡笔场

蜡笔细条表达“某种事物持续存在或传播”；蜡笔场表达“某种事物已经成为广泛
覆盖当地社会生活的环境”。`crayonStrip` 是持续性抽象对象的默认值，
`crayonField` 是逐 EntityPhase 审核后的例外升级。

技术、生产系统、贸易网络、艺术传统、哲学传统、商品、器物类别、文化传统、
文学传统、神话传统和文献集合默认使用细条。语言、文字系统和宗教传统也不能
仅凭 Entity 类型自动成为场；地方语言、行政语言、少数书吏使用的文字系统或
局部宗教传统都可能仍是细条。

条／场判断属于 Phase，因为同一 Entity 在不同时间和 Region 的社会覆盖程度
可能不同。派生语义使用：

```ts
interface PresenceProfile {
  phaseId: EntityPhaseId;
  presenceMode: 'tracked' | 'pervasive';
  regionIds: readonly RegionId[];
  rationale: string;
  sourceIds: readonly SourceId[];
}
```

规则如下：

- 没有 profile 时必须默认为 `tracked`；
- `tracked` 生成 `crayonStrip`；
- `pervasive` 生成 `crayonField`；
- `pervasive` 必须记录适用 Phase、Region、理由和有效 Source；
- profile 属于可验证的可视化语义层，不得改变或伪造 V6 历史核心；
- 第一版宁可少画场，也不能夸大某个现象对社会生活的覆盖。

## 5. 不确定性与形状的关系

时间和 Region 的 `approximate` 只表达不确定性，不决定五种标记中的哪一种：

- 时间近似：横向端点粗糙、渐散或使用不确定须线；
- Region 近似：地域边缘更稀疏、断续或渐散；
- 近似政权仍是中部实心的 `block`；
- 时间明确的文学传统仍是 `crayonStrip`；
- `pervasive` 仍需要独立来源，不可从 `approximate` 推导。

不透明度不得被当成史实确定性的唯一编码。实体块保持实体感，只在不确定边界
变化；蜡笔材料感表示存在方式，不等于“内容不可靠”。

## 6. Region×时间切片

第一轮切片以时间为横轴，以 Region 为纵轴：

- 大区作为分组标题；
- 细分 Region 作为数据行；
- 只挂在大区的记录进入“大区未细分”行，不扩散到所有子区；
- “未细分”是证据不足时的安全收纳机制，不是长期占位方案；一旦来源能够支持
  子区归属，作者必须显式拆分到子 Region，不得为了省事继续直挂大区；
- 标记为 `associationPolicy: 'groupOnly'` 的大区只承担分组和折叠身份，任何
  EntityPhase 或 Event 都不得直接引用，也不会生成“未细分”行；作者必须选择
  有来源支持的子 Region，无法判断时暂缓该地域关联；
- Region 排列是文化—地理浏览顺序，不声称各行间距等于真实地理距离；
- 默认只显示实际有数据的 Region，可以另设“显示空白骨架 Region”的非默认
  选项；
- 有数据的大区默认折叠；折叠行必须保留当前概念层与时间窗口中的压缩历史带，
  不能退化为空白标题；
- 展开状态以大区 Region ID 为唯一身份，跨概念层共享并保存到本机。用户展开
  “两河流域”后，切换概念层或刷新预览都不需要逐层重新展开；
- 一个 Phase 涉及多个 Region 时，只在声明的 Region 绘制；
- 相邻且连续的 Region presence 可以合成连续图形，非相邻 Region 之间不得
  自动填空。

同一 Entity 在同一 Region 行中的 `block` Phase，如果时间首尾相接或重叠，
renderer 必须把它们组合为一条连续视觉带。组合只发生在展示层：原 Phase 身份、
时间、Region 和来源仍然保留，并可以用细微内部界线提示阶段边界；只要存在真实
时间空档，就必须断开，不能靠视觉插值补齐。历史年份相邻也属于首尾相接，例如
公元前1765年之后紧接公元前1764年；跨纪元时公元前1年之后紧接公元1年，不制造
公元0年。

EntityPhase 的切分必须对应可见的空间状态变化，而不是把历史叙事分章投射到
时间轴。政权只有在 Region 覆盖集合增加或减少时才分段；换任统治者、战争、
改革、兴盛或衰落不单独切开矩形，只改变 RegionalRole 文字也不构成疆域变化。
其他 Entity 只有在 Region 或 RegionalRole 改变时才分段。相邻空间签名相同的
Phase 必须合并；如果 Region 目录过粗，先细化 Region 或暂缓表达，renderer 不得
根据“扩张期”“末期”等标题制造视觉断点。

被接受的 Event 必须显式填写唯一 `conceptLayerId`，不能因为对象类型叫 Event
就自动进入“事件、战争与迁徙”。当前复审阶段把全部 `historicalProcess` 隔离在
非运行时 `pending` 清单中，因此第一轮预览只消费已接受的 `historicalEvent`；
未来获批的过程才使用 `trace`。这种隔离发生在 V6 集成边界，不由 renderer
猜测或隐藏。Entity 同样只进入自己的主要概念层。第一轮不从 TemporalRelation、
候选关系或 secondary concept 生成副本。

## 7. 重叠与局部分轨

`block`、`node` 和 `trace` 的视觉碰撞只在实际冲突的时间段产生局部分轨：

1. 单个活动对象使用完整 Region 行；
2. 两个或更多实体标记发生屏幕碰撞时，仅在该区间分成稳定的平行窄轨；
3. 碰撞结束后立即合并回完整行；
4. 同一 Entity 在同一 Region 的相接、重叠或相邻日历年 `block` Phase
   先合为一个视觉带再参与碰撞，不得因自己的多个 Phase 发生分轨；真正时间
   间隔仍分开。视觉带用一个连续填充轮廓，内部阶段只用淡线标记；
5. 稳定排序必须保证刷新、缩放和输入顺序变化不会让标记来回交换；
6. 菱形的最小屏幕尺寸也参与碰撞判断。

`crayonStrip` 和 `crayonField` 不参与实体分轨，可以直接重叠，重叠处让笔触
密度自然加深。hover 可以列出同一位置的多个命中对象；持久选择一次只能保存
一个知识主体。点击具体图形选中其 Entity 或 Event 身份，而不是 Region＋时间
坐标；同一 Entity 的全部可见 Phase 和 Region 片段必须同时高亮，其他对象降权。
hover 内容必须使用不参与页面排版的浮层。持久选择详情在桌面端占用稳定侧栏，
移动端使用固定底部覆盖层；它们都不得插入图表上方或改变图表位置，以免形成
“浮层出现—目标移动—浮层消失”的悬停循环。详情按知识主体聚合：Entity 名称只
出现一次，每个 Phase 只出现一次，同一 Phase 的多个 Region 合并在一行列出。

## 8. Renderer-neutral 数据流

数据流固定为：

```text
V6 knowledge core
→ visualization semantics
→ KnowledgeSpaceMark
→ SliceSpec projection
→ local layout
→ SVG renderer（第一轮）／WebGL renderer（未来）
```

`KnowledgeSpaceMark` 至少表达 subject、Phase/Event、时间范围、Region presence、
概念层、mark kind、时间／Region 不确定性和稳定 texture seed。它不得包含 SVG
path、像素位置、DOM 节点或 Three.js 对象。

EntityPhase 标记必须以稳定的 Entity 名称作为主标签；简短 Phase 标题只能作为
副标签。Entity 可以没有 Phase，预览不得为了让它出现而制造“长期延续”式时间条。
EntityPhase 不拥有独立概念层；若一段内容需要进入另一概念层，它应归属于另一个
Entity、Event 或 TemporalRelation。

当前第一版只把 Entity 主名称写入 `block` 内部，并在空间不足时截断；`node`、
`trace`、`crayonStrip` 和 `crayonField` 暂不绘制常驻名称，仍通过 hover、键盘
焦点和选中详情读取身份。不得为了“标题完整”把其他四类名称提前堆到图上。

政权层按用户要求进一步简化：每个政权只保留一个常驻名称，优先放在首都所属
地域的最长可见连续条块中。没有单一首都的文明使用代表性核心地域；这是标签
锚点，不增加精确首都定位或归属关系。锚点集中在 `preview/polity-labels.ts`。
其他地域保留同色条块和完整的悬停、键盘、选中详情；核心地域折叠时不把名称
移到外围地域。其他概念层的标签规则保持原样。

2026-09-15 政权总览复核：古巴比伦向幼发拉底河中游、南部美索不达米亚的
短期扩张支线仅留在详情；亚述和新巴比伦在南黎凡特的概括性影响也仅留详情，
不再与当地王国平分块面。白名单及理由维护在 `adapters/polity-overview.ts`，
在投影前应用，原始阶段和证据保持完整；规则必须匹配现有阶段、地域和角色，
失配立即报错，不能用于隐藏无效数据。没有总览条目的地域不保留空行。

南黎凡特的政权重叠组使用固定位置：先为当地核心政权安排位置，一次分配
整组的槽位，邻居结束后保留空位，避免犹大反复变形。此局部规则不修改其他
地域的二分、三分样式；高度只服务排布，不表示领土占比。阿卡德—乌尔的
断代与地域审核另见 `docs/reviews/akkad-transition.md`，黎凡特角色审核见
`docs/reviews/levant-polity-overlap.md`。

政权块面统一使用垂直起止边，分叉和合流采用约 5 屏幕像素的短斜边。过渡
限制在相邻段长度的四分之一以内，短重叠自动缩短；收窄发生在新对象出现前，
扩宽发生在旧对象结束后，避免过渡侵入相邻色块。每条连续带仍由一个封闭路径
填充，历史起止位置、真实空隙和阶段边界保持不变；约略年代仍在详情中标明。
一般政权行按原始开始年代决定上下顺序，同期对象以稳定身份排序，不因窗口
截断改用可见开始点。二分、三分统一等高和间隙，重叠结束后回到完整高度。
南黎凡特沿用已批准的固定槽位例外。其他概念层的标记形状不变。

Phase 标题在存在时必须说明空间差异，例如“控制范围扩展至努比亚”或“分布转向
爱琴海岛屿”；“早期”“鼎盛期”“统治期”“末期”一类纯年代或叙事标题不能承担
空间建模。单一空间状态可以省略 Phase 副标题，由 Entity 名称承担主标签。

第一轮使用 React、TypeScript 和 SVG。不得为预览增加另一个客户端框架或远程
运行时。未来实施 3D 时另行做依赖与架构审批，并优先动态加载 3D renderer，
避免增加 V5 首屏负担。五种二维标记可在 3D 中分别映射为盒体／薄板、八面体／
图标平面、管线／胶囊、丝带和粒子／体积笔触，但这些只是 renderer 表达，不能
反向成为历史数据。

## 9. 本地预览边界与交互

预览使用独立的 `knowledge-space-preview.html`／TypeScript 入口和专用 Vite
配置。运行 `pnpm dev:v6-preview` 会在本地服务器中打开它；生产式本地验收使用
`pnpm check:v6-preview`。它不得被正式 V5 entry graph、正式 `pnpm build`、
Pages workflow 或 `dist/` 部署产物导入。UI 单元测试与布局测试使用小型稳定
fixture，只有最后的集成验收读取完整 V6 knowledge core。

第一轮界面包含：

- 八个概念层的单选控制，默认“政权、制度与社会”；
- 当前时间窗口、缩放和平移；
- 粘性的时间轴和当前 Region 分组标题，不另设粘性概念切面状态栏；
- 默认折叠、跨概念层和刷新持久化的大区控制，以及折叠状态的压缩历史带；
- 鼠标、键盘和触摸选择；
- 不改变图表排版的 hover 浮层，以及桌面侧栏／移动端底部覆盖层中的单一知识
  主体详情；
- 同一 Region 行内相接 `block` Phase 的连续视觉带，以及仅限 `block` 的内嵌
  Entity 名称；
- 重叠对象列表；
- reduced-motion 和无需 hover 的移动端交互。

界面必须使用面向读者的历史名称，不能把 `Entity`、`EntityPhase`、`markKind`
等内部词作为常规文案。

## 10. 阶段门禁

### 埃及文明视觉样板（用户批准）

埃及对象跨概念层共用金／黄赭色系，古、中、新王国通过同色系明暗区分。色彩
依据和逐对象文化关联在预览的 `egypt-theme.ts` 中维护；具体色值是可读性设计，
不宣称旗帜复原。共享战争、条约、交流文本不根据位置自动染成埃及色。

尼罗河谷与三角洲的展开行允许显示浅金文化背景，以及一次原创简化狮身人面像

### 文明配色与背景扩展（用户批准）

所有现有政治社会对象的颜色由 `subject-colors.ts` 汇总，埃及保持已批准色系，

背景范围唯一维护于 `civilization-backdrops.ts`，涵盖四个主要古代文明区域及

重叠。埃及维持用户指定范围，其余依据现有阶段及注明的考古来源选定。

所有标识为原创简化 SVG，不含伪造铭文或现代旗帜，不宣称器物复原；图案作为
整段文化的识别符号，不把代表器物的年代推广到整段。背景不加常驻文明名称，
每个展开分组内每段背景只绘一次标识。按用户修正，所有格子保持原有尺寸，
不增加底部标识空间；所有标识采用埃及样板的大幅浅色水印样式，位于内容后方。

为 `referenceTimeSpan`；设计窗口不构成新历史断代，也不改变前景对象年代。
折叠概览继续使用同一套对象颜色。所有背景仍不可交互，不进入知识核心或 V5。

1. 修正具体文学作品与文学传统的数据身份；
2. 建立 Phase 级 PresenceProfile 和条／场验证；

每一阶段必须先通过自己的类型、负面测试和 fixture 门禁，再由唯一 Integration
Agent 接入共享配置。renderer 不得过滤无效数据来让页面看似正常。

Region×时间预览；V5 正式网站、正式构建和 GitHub Pages 行为保持不变。关系、
